# 배포 조합 관리 화면

## 이 프로젝트를 처음 열었다면

[HTML 개발 안내서](../../docs/mfe-project-handbook.html#project-platform-admin) · [실행·발행 순서](../../docs/mfe-project-handbook.html#workflow) · [플랫폼 제공 목록](../../docs/mfe-project-handbook.html#platform)

- 담당: 플랫폼 팀 / 운영 담당.
- 목적: 버전 선택·롤백·지원 종료·삭제 판단을 파일 수작업 대신 화면으로 처리합니다. 제품 조합과 독립적으로 배포합니다.
- 사용: 통합 서버의 /admin에서 사용합니다. 자체 React 앱이며 제품 SDK·Shell을 import하지 않습니다. mf.config.cjs의 kind: shell은 HTML 진입 앱이라는 빌드 분류입니다.
- 수정 시점: 관리 기능과 표시를 바꿀 때 수정합니다. integration의 build:admin이 이 앱만 빌드·발행하고 admin.json을 바꿉니다. 제품 current.json은 유지합니다.

---

SDK·B·D의 현재 의존 관계, 버전 선택, 적용 전 검사, 저장된 조합으로의 롤백을 제공하는 독립 React 프로젝트다. 제품 Shell이나 런타임 SDK를 가져오지 않으므로 서비스 조합을 롤백해도 관리 화면에 접속할 수 있다.

자체 package.json·lockfile·vendor 빌드 도구·src·dist를 갖는다. Node.js 24 권장.

```sh
npm ci
npm run build
```

화면과 API는 로컬 저장소 서버가 함께 제공한다. `integration`에서 `npm run build:admin`으로 관리 화면만 빌드·발행한 뒤 `npm start`를 실행하고 <http://127.0.0.1:4173/admin>에 접속한다. 관리 화면 발행은 서비스의 `current.json` 조합을 바꾸지 않는다.

버전 선택 → 변경 내역 확인 → 조합 검사 → 변경 적용 순서로 사용한다. 다른 관리 화면이나 CLI가 먼저 조합을 바꾸면 적용을 거절한다. 이력에서 불러오기는 미리보기만 준비하며, 검사 후 롤백 버튼을 눌러야 적용된다. 구버전 파일은 삭제하지 않는다.

이 화면은 로컬 실행용이다. 동일 출처 요청 검증과 변경 충돌 방지는 포함하지만 사용자 인증·팀별 권한·운영 감사 로그는 구현하지 않았다. 저장 시각은 조합 파일의 최초 생성 시각이다. 호환성 검사는 선언된 범위와 그래프를 검사하며 의미적 API 호환성 검증은 별도로 필요하다.

`/admin#lifecycle`의 **사용 현황 · 지원 종료**에서 배포물별 현재 사용 경로, 열린 탭, 롤백·고정 참조, 종료 예정일·공지 기록과 삭제 보류 사유를 확인한다. 정책 수정에도 별도 revision 검사를 적용한다. 종료일은 한국 시간의 해당 날짜 마지막까지 지원한다는 뜻이다.

지원 종료일이 지나면 신규 선택을 막는다. 현재 조합의 정확히 같은 사용 경로를 유지하는 것은 허용하지만, 새로운 소비 경로나 간접 참조를 추가하거나 다른 버전으로 전환한 뒤 종료 버전으로 롤백하는 것은 거절한다. UI·API·CLI가 같은 서버 검증을 사용한다.

**등록 해제 준비 → 전체 배포 ID·사유 입력 → 등록 해제 실행**은 선택 목록에서 제외하고 파일을 보관한다. 지원 종료·공지 기록 후 30일·현재 조합 미사용이 조건이다. 열린 탭과 롤백 참조는 그대로 보호한다.

**파일 삭제 준비 → 전체 배포 ID·사유·관측 범위 밖 미사용 확인 → 파일 삭제 실행**은 로컬 저장소 파일을 실제 제거한다. 등록 해제·지원 종료·공지 유예 종료·마지막 관측·탭 정리 중 가장 늦은 시점부터 30일 보존, 관측 시작 후 30일이 필요하다. 현재 사용·열린 탭·확인 불가 탭·롤백·고정 참조가 남으면 서버가 거절한다.

상세의 ‘롤백 보관·고정 참조’에서 과거 조합을 명시적으로 보관 해제할 수 있다. 조합 기록은 남지만 재선택·롤백과 해당 HTML 새 진입은 차단한다. 현재 조합은 보관 해제할 수 없다. 보관 해제가 열린 탭 보호를 없애지는 않는다.

배포 정보와 작업 시각·사유는 삭제 뒤에도 남긴다. 등록 해제된 ID는 재발행으로 복구할 수 없으며 새 배포 ID가 필요하다. 삭제 미완료 상태는 조건을 다시 확인하고 남은 파일 삭제를 재시도한다. 서버가 작업 직전에 모든 조건을 잠금 안에서 다시 확인한다.

로컬 서버가 서비스 HTML 응답에 관측 스크립트를 추가한다. 서비스 번들은 다시 빌드하지 않는다. 새로 연 탭은 15초마다 조합과 로드된 container를 보고한다. 120초 동안 응답이 없으면 종료 여부 확인 불가로 남겨 삭제를 보류한다. 추적 도입 전 탭, 다른 호스트·CDN, 전송 실패로 아예 등록되지 않은 탭은 관측할 수 없으므로 ‘삭제 검토 가능’은 최종 삭제 승인이 아니다.

**응답 없는 탭 정리**에서 재개 보호 유무, 사용 기한, 정리 가능 시각을 확인한다. 새 Shell의 보호 탭은 5분 기한을 15초마다 갱신한다. 기한이 만료되면 조작·추가 로딩이 잠기며 최신 화면을 열어야 한다. 만료 후 24시간이 지나면 전체 탭 ID와 사유를 확인해 참조를 정리할 수 있다. 정상 응답 중인 탭은 정리할 수 없으며 보호 기능 없는 기존 탭은 아래의 별도 경로를 사용한다. 서버가 응답 순서와 기한을 실행 직전에 다시 검사한다.

참조 정리 기록은 남고 지연 응답으로 되살리지 않는다. 그 탭이 사용한 전체 조합에 적용되며 파일은 삭제하지 않는다. 정리 시점부터 최소 30일 더 보존하고 다른 탭·현재 조합·롤백·고정 참조는 계속 삭제를 막는다. 새 보호는 Shell을 한 번 수정·빌드해 도입했으며 이전에 열린 탭에는 소급 적용되지 않는다.

**구형 탭 전환 · 접근 종료**에서는 먼저 ‘이 브라우저의 전환 중계 연결’로 같은 브라우저·프로필·출처의 구형 탭을 연결한다. 서버 명령을 읽지 않는 원래 코드에도 적용되며, 다른 브라우저까지 원격 설치되지는 않는다. 대상 탭 ID·사유·입력 손실 확인 후 전환을 요청한다. 별도 전환 문서가 실제로 열린 뒤 확인 요청이 와야 참조를 해제한다. 요청 대기·24시간 만료·전환 확인을 구분하며 확인 실패는 그 문서에서 재시도할 수 있다. 새 서비스 전체의 작동을 보증하는 확인은 아니다.

장기 미응답 탭은 ‘버전 접근 종료 준비’로 해당 배포 ID의 서버 파일 제공을 먼저 종료한다. 등록 해제, 현재 미사용, 롤백·고정 참조 없음, 보호 탭 없음, 구형 탭 응답 24시간 이상 없음이 필요하다. 복귀 탭의 서비스 중단과 서버 밖 사용 확인을 명시적으로 받는다. 파일은 남아 있지만 410을 반환한다. 그 후 24시간 유예를 거쳐 ‘이 버전 참조 정리 준비’를 실행할 수 있다. 같은 탭의 다른 버전 참조는 유지한다.

접근 종료·참조 정리도 보존 기준에 포함해 최소 30일 뒤 기존 삭제 검사를 수행한다. 지연 응답으로 정리된 버전을 부활시키지 않으며 다른 버전의 응답 기록은 갱신한다. 이미 받은 코드·업무 API·외부 저장소를 회수하는 기능은 아니므로 해당 범위는 별도 운영 조치가 필요하다. 이번 추가는 서버·관리 화면만 수정하며 SDK·Shell·A·B·C·D를 재빌드하지 않는다.

## 서비스 · 메뉴 (1.1.0)

`/admin#services`에서 발행된 업무 Remote와 공개 모듈, 메뉴 ID·표시 이름·주소를 등록한다. 하위 runtimeDependencies도 선택한다. 조합 검사 후 적용하며 편집하면 검사를 다시 해야 한다. 새 탭부터 반영하고 이력 롤백으로 메뉴도 복원한다. 현재 Shell이 registered-menu-v1을 지원하지 않으면 추가 기능을 잠그고 최초 전환을 안내한다.

현재 관리 화면은 파일 업로드 기능이 아니다. 서비스 팀/CI가 먼저 기존 publish 경로로 배포 파일을 발행한다. 지원 종료·등록 해제 항목은 신규 선택할 수 없다. 메뉴 제거는 현재 연결만 제거하며 파일은 사용 현황·등록 해제·삭제 절차에서 별도로 관리한다. [전체 사용법](../../docs/mfe-project-handbook.html#registered-services).

## 대시보드 위젯 (1.2.0)

`/admin#dashboard`의 DashboardEditor.jsx에서 서비스가 release.widgets에 공개한 위젯만 선택한다. 일반 exposes 전체를 선택 가능하게 만들지 않는다. 배치 ID·표시 제목·순서·1/2칸 너비를 정하고 미리보기 → 조합 검사 → 적용한다. 배치 미리보기는 상자 모양만 그리며 업무 코드를 로드하지 않는다.

같은 위젯을 여러 ID로 복제할 수 있고 다른 서비스 버전도 함께 선택한다. 하위 runtimeDependencies 선택은 DependencyFields를 페이지 메뉴와 공용으로 사용한다. 같은 배포 ID의 하위 선택은 모든 배치/사용처가 공유한다. 지원 종료/등록 해제 항목은 신규 선택할 수 없다.

배치 제거·빈 대시보드 저장은 파일 삭제가 아니다. 이력에는 위젯 개수를 표시하며 롤백은 순서·너비·제목·버전·페이지 메뉴를 함께 복원한다. 새로운 기능은 Shell 1.3.0과 최신 서버가 필요하며 SDK는 기존 1.3.1을 사용한다. [사용법](../../docs/mfe-project-handbook.html#dashboard-widgets).
