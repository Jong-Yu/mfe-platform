이 폴더 하나가 실행 단위입니다. 다른 예제·상위 프로젝트·latest.json을 가져오지 않습니다. 같은 기반 코드도 자체 사본입니다. 이 문서는 폴더를 다른 위치로 옮겨도 함께 사용할 수 있습니다.
01 · 먼저 실행

첫 화면까지

Node 22.9 이상과 npm이 필요합니다. 제공된 번들로 실행할 때는 integration의 의존성만 설치하면 됩니다.

cd 14-region-retry
npm --prefix integration ci
npm start

http://127.0.0.1:4514를 여세요. 포트가 사용 중이면 PORT=4600 npm start. 종료는 터미널에서 Ctrl+C입니다. 다른 예제와 기본 포트가 달라 함께 실행할 수 있습니다.

소스까지 개발할 때는 예제 루트에서 npm run setup을 실행합니다. 각 프로젝트의 lockfile로 의존성을 설치하며 npm workspace를 만들지 않습니다. 인터넷이 없는 검증 환경에서는 미리 채운 npm 캐시와 MFE_OFFLINE=1을 사용할 수 있습니다.

02 · 이 예제가 보여 주는 것

따라 해 보기

A 1.1 ──→ B 1.4 ──→ D 1.0
   └────→ C 1.1 ──→ B 2.1 ──→ D 2.0
             한 문서의 공통 SDK는 하나

이번 단계의 핵심 구현: A 프로젝트의 src/RemoteRegion.jsx + remote-loader.js. 12는 정상 실행만, 13은 실패 격리만, 14~15는 서비스 내부의 재시도, 16은 SDK 공통 컴포넌트, 17은 SDK 재시도 정책의 런타임 교체입니다.

npm test는 필요한 C·B·D 요청을 실제 HTTP 503으로 실패시킨 뒤 복구합니다. 14~17에서는 직접 B의 DOM·입력·카운터가 유지되고 C 영역만 다시 나타나는지 확인합니다. 13에는 재시도 버튼이 없습니다.

선택 명령의 프로필초기 조합과의 차이
baseline초기 고정 조합
npm run select -- baseline
# 이 예제는 baseline 하나를 제공합니다.
npm run reset

select는 새 탭의 조합을 바꿉니다. reset은 이 예제의 실험 저장소를 제공된 seed-store로 되돌립니다. 초기화 전에 이 예제 서버와 탭을 닫으세요. 소스 수정은 reset으로 되돌리지 않습니다.

03 · 수정할 위치

폴더와 책임

projects 하위 프로젝트역할
platform-build-tools플랫폼 빌드·개발 Host 도구 소스. 실제 서비스 빌드는 vendor의 잠긴 도구 버전을 사용.
platform-sdk플랫폼 팀이 제공하는 MF 원격 SDK. Context, 상태 경계, 필요한 공통 UI를 제공.
service-d-v1B 1.x가 가져오는 D 1.0 데이터 모듈. 백엔드 HTTP API가 아닌 MF 모듈.
service-d-v2B 2.x가 가져오는 D 2.0 데이터 모듈.
service-b-v1B 1.4의 독립 소스. 자체 상태와 CSS, D 1.x 의존성을 가짐.
service-b-v2B 2.1의 독립 소스. D 2.x를 사용하며 B 1.x와 동시에 실행.
service-cB 2.x를 사용하는 서비스.
service-aB 1.x를 사용하는 서비스. 중첩 예제에서는 C도 사용.
shell사용자가 여는 앱. SDK Provider를 한 번 설치하고 헤더·사이드바·서비스 영역을 조합.
  • src/: 실제 편집할 화면·모듈. mf.config.cjs: 공개할 모듈과 위젯. mf.dependencies.json: 빌드 고정 대상 또는 런타임 허용 범위.
  • package.json / package-lock.json / vendor/: 라이브러리와 빌드 도구 고정. SDK는 npm 설치하지 않고 MF로 실행합니다. vendor의 npm 패키지는 빌드·개발 도구입니다.
  • integration/tools/: 이 예제만의 서버·등록부·검사 코드. 예제별 테스트는 verify.mjs와 필요한 integration/tests/에 있습니다.
  • composition.config.json: 사용할 프로젝트와 의존 관계·대체 조합. seed-store/: 제공된 초기 배포물. artifact-store/: 실행 중 수정하는 사본.
  • example.lock.json: 소스·설정·lockfile·도구 tarball·배포 파일의 SHA-256. npm run pins로 제공 상태와 비교합니다. 의도적으로 편집하면 차이가 보고되는 것이 정상입니다.
# 예: A 서비스 수정 후, A만 빌드·발행
npm run build -- service-a
# 현재 소스의 배포 ID로 조합을 명시적으로 적용
npm run select -- baseline
# 새 탭에서 확인

# 예제 전체를 소스부터 다시 빌드하려면
npm run setup
npm run build
npm run select -- baseline

기본 조합을 직접 바꾸려면 composition.config.json의 profiles를 편집합니다. 이미 실행 중인 탭에 SDK나 서비스 버전을 강제로 바꾸지 않습니다. build는 발행까지만 하고, select는 적용을 담당합니다. 고정 의존성을 바꾸면 해당 소비자도 재빌드해야 합니다. 01·02에서는 D → B → A/C 순서가 필요합니다.

플랫폼 팀은 SDK·Shell·개발 Host 도구·계약 검사·등록부를 제공합니다. 서비스 팀은 자체 콘텐츠와 공개 모듈, 의존 범위를 개발합니다. 일반 서비스 화면에 운영용 헤더·사이드바를 중복 구현하지 않습니다. 개발 Host가 제공하는 Layout은 단독 개발용입니다.

React/React DOM은 각 프로젝트의 잠금 파일로 고정하고, 문서 안에서는 공통 인스턴스를 공유합니다. 플랫폼 도구 소스를 수정할 때는 새 버전으로 pack한 뒤 해당 서비스의 vendor·의존성·lockfile을 갱신해야 적용됩니다. 공통 도구 폴더를 편집했다고 다른 서비스의 잠긴 tarball이 바뀌지 않습니다.

현재 작업본과 보존된 소스맵을 바탕으로 분리한 교육용 스냅샷. 과거 각 시점 전체 저장소의 원본 복원이 아님. 오류 격리 이전/이후와 SDK 이전/이후는 각각 별도 소스로 만들었습니다. 관리 예제들은 동일한 운영 기반을 자체 복사하여 사용하며 역사적으로 기능이 추가된 정확한 시점의 전체 코드 복원본은 아닙니다.
