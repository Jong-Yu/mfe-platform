INDEPENDENT MFE EXAMPLE · 20

사용자마다 다른 버전을,
안전하게 구독하기.

한 사람의 선택이 다른 사람이나 이미 열린 탭을 바꾸지 않도록 합니다. 화면을 열지 않은 사람의 구독도 삭제 검사에 포함합니다.

1. 이 폴더만 실행하세요

cd examples/20-user-subscriptions
npm --prefix integration ci
npm start

사용자별 구독 화면에서 시작합니다. 사용 현황·삭제 관리는 별도 화면입니다. Node 22.9 이상과 npm이 필요하며 다른 예제나 원래 프로젝트는 필요하지 않습니다.

기본 포트는 4520입니다. 다른 포트를 쓰려면 PORT=4600 npm start. 종료는 Ctrl+C입니다. seed-store의 초기 배포물을 artifact-store에 복사하여 사용합니다.

Alice·Bob·Carol 선택은 로컬 데모 로그인입니다. 같은 브라우저 프로필의 탭은 로그인 쿠키를 공유합니다. 서로 다른 사용자 비교에는 별도 프로필이나 일반 창·시크릿 창을 사용하세요. 한 사용자의 이전 탭과 새 탭은 같은 프로필에서 비교합니다.

2. 세 사용자로 비교하세요

  1. Alice: “현재 운영” 조합을 선택하고 B 1.4.0 차량 선택 위젯을 추가합니다. B 2.1.0도 함께 추가할 수 있습니다. 조합 검사 → 내 구독 저장 → 내 대시보드 새 탭을 누릅니다.
  2. Bob: 다른 브라우저 프로필에서 “이전 운영” 조합과 B 2.1.0을 저장하고 대시보드를 엽니다. 각 사용자의 이름·위젯 버전과 카운터·메모가 독립적인지 확인합니다.
  3. Alice 변경: 편집 화면에서 B 1.4.0을 B 1.5.0으로 교체해 저장합니다. 새 탭은 1.5.0, 기존 탭은 1.4.0과 기존 입력을 유지합니다. Bob의 구독은 그대로입니다.
  4. Carol: B 1.4.0 구독만 저장하고 대시보드를 열지 않은 채 브라우저를 닫습니다.
  5. 관리 화면: B 1.4.0과 D 1.0.0을 선택합니다. “저장된 사용자 구독”에 Carol과 사용 경로가 표시됩니다. 접속하지 않았어도 등록 해제·삭제를 막습니다.
  6. 해제: “내 구독 해제” → “해제 확인”. 저장된 구독 참조는 없어지지만 기존 탭·롤백·공지·보관 조건이 남으면 파일은 삭제되지 않습니다.

제공 상태에는 사용자 구독이 없습니다. “현재 운영”은 A → B 1.5 → D 1.1, “이전 운영”은 A → B 1.4 → D 1.0입니다. 두 조합의 C는 B 2.1 → D 2.0을 사용하며 SDK는 모두 1.3.1입니다. 사용자별 위젯 배치를 그 위에 추가합니다.

3. 버전 이름 대신 완성된 조합을 저장합니다

사용자 Alice ──→ 저장된 구독 revision 2
                 ├─ 선택한 기본 배포 조합 ID
                 ├─ 위젯 배포 ID · 공개 위젯 ID · 배치
                 └─ 해석이 끝난 전체 조합 ID
                      ├─ Shell / SDK / A / C
                      ├─ B별로 선택한 D 배포 ID
                      └─ 개인 대시보드 B 1.5 + B 2.1

기존 Alice 탭 ──→ 처음 받은 조합 (독립적인 탭 보호)
새 Alice 탭   ──→ 현재 저장된 구독
Bob의 탭      ──→ Bob이 저장한 구독

서버는 SDK 지원 범위·공개 위젯 계약·하위 의존성·순환 관계·지원 종료 상태를 확인하고 불변 조합을 만듭니다. 새 위젯의 하위 버전은 플랫폼이 공개한 정확한 기본값에서 가져옵니다. 기본 조합에 이미 있는 배포물은 그 조합의 의존 선택을 따릅니다. latest나 가장 높은 버전을 자동 선택하지 않습니다.

한 문서 안의 SDK는 하나입니다. 다른 B 버전은 MF 컨테이너와 CSS 이름을 구분하고, 같은 B의 복제는 배치 ID로 상태를 구분합니다. 서버가 확인한 사용자 정보를 Shell의 PlatformProvider에 전달합니다. 위젯 팀이 사용자별 props를 새로 정의하지 않습니다.

동일한 선택을 한 사용자들은 같은 불변 조합 파일을 참조할 수 있습니다. 소유권은 사용자별 레코드에 따로 저장합니다. 한 사용자가 해제해도 다른 사용자의 참조가 남으면 보호가 계속됩니다. 요청 본문의 userId로 다른 사용자의 구독을 수정할 수 없습니다.

행동결과
조합 검사검증만 수행. 구독 저장·전역 current 변경 없음.
내 구독 저장내 레코드와 불변 조합 저장. 새 탭부터 적용.
전역 조합 변경이미 저장된 개인 구독은 그대로 유지.
오래된 편집 화면에서 저장revision이 다르면 409로 거부. 최신 구독을 불러와 다시 검사.
지원 종료새 사용자·새 경로의 선택 차단. 기존 사용자의 동일 참조는 유지 가능.
구독 해제내 활성 참조 제거. 기존 탭이나 배포 파일은 즉시 제거하지 않음.

4. 접속 여부와 사용 권한을 분리합니다

보호 근거보호 대상해제 조건
저장된 사용자 구독SDK·Shell·위젯과 전이 의존성 전체. 미접속 사용자 포함.버전 전환 또는 명시적인 해제. 자동 만료 없음.
화면 열기 예약HTML을 받은 뒤 탭 보호를 시작하기 전의 조합.30초 후 만료. 만료된 예약으로 새 탭 시작 불가.
기존 탭처음 받은 조합. 아직 로드하지 않은 의존성 포함.정상 종료 또는 사용 기한·유예 기간·명시적 탭 정리 절차.
전역 현재 조합·롤백·고정 소비자기존 운영 정책의 참조.각 참조를 별도로 전환·해제.

구독 저장·해제, 조합 보관 해제, 등록 해제와 파일 삭제는 동일한 쓰기 잠금을 사용합니다. 삭제 요청 시 최신 구독과 탭을 다시 검사합니다. 이전에 표시된 “삭제 가능” 상태만 믿고 삭제하지 않습니다.

활성 구독이 사용하는 기본 조합과 개인 조합은 보관 해제를 막습니다. 개인 구독의 이전 조합 파일은 기록으로 남겨도 자동으로 영구 롤백 참조가 되지는 않습니다. 아직 사용하는 사용자나 탭이 있으면 각각의 참조로 보호합니다.

활성 구독이나 열기 예약이 있으면 등록 해제와 파일 제공 차단도 막습니다. 모두 전환·해제한 뒤에는 기존 탭을 보호하면서 등록을 해제할 수 있습니다. 실제 파일 삭제는 열린 탭까지 해소하고 공지·관측·보관 기간을 충족해야 합니다. 마지막 구독 참조 해제 시각도 보관 기간 계산에 포함합니다.

기본 정책은 공지 유예 30일·관측 30일·보관 30일입니다. 보관은 등록 해제·마지막 사용·구독 해제 등 가장 늦은 시점부터 계산합니다. 탭은 15초마다 갱신하며 사용 기한 5분, 만료 후 정리 유예 24시간입니다. 구독 자체에는 탭 시간 제한을 적용하지 않습니다.

서비스 팀은 위젯과 SDK 계약을 유지하고 공개 위젯을 배포합니다. 플랫폼 팀은 사용자별 해석·저장·실행, 공통 Provider, 수명 관리와 도구를 담당합니다. 구독을 바꿀 때마다 서비스 팀의 코드 대응이나 재빌드는 필요하지 않습니다.

새 기본 조합과 위젯 의존 선택은 composition.config.json의 subscriptionProfiles·subscriptionWidgetBindings로 정하고 publish:options로 공개합니다. 사용자가 이미 저장한 조합을 바꾸지 않습니다. 지원 종료된 선택지를 새로 공개할 수 없으므로 종료된 조합은 공개 목록 설정에서 제거해야 합니다. seed는 초기 배포물 작성용이고, 사용자 구독이 있는 저장소에서는 실행을 거부합니다.
